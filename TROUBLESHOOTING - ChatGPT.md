Good question — and this is **exactly where Panda monorepo setups confuse people**. Let’s reset it cleanly.

------

# 1️⃣ What `apps/client/styled-system/` is for

This folder is **generated by Panda for the client application**.

It contains things like:

```text
css/
tokens/
patterns/
jsx/
styles.css
```

These are **runtime utilities for the app**.

They provide:

- `css()` function
- `cx()`
- JSX styled components
- token access
- compiled style utilities

In other words:

```text
apps/client/styled-system
↓
runtime styling utilities for the CLIENT app
```

This is **generated from the client's `panda.config.ts`**.

------

# 2️⃣ What `packages/design-system/styled-system/` is for

This is **generated by Panda for the design system package itself**.

It exists so the DS can:

- define recipes
- define tokens
- build styles
- export styling helpers

Example usage inside your DS:

```ts
import { cva } from '../styled-system/css'
```

So:

```text
packages/design-system/styled-system
↓
styling runtime used internally by the design system
```

This is generated from:

```text
packages/design-system/panda.config.ts
```

------

# 3️⃣ Are BOTH Necessary?

### In a monorepo with a design system

Yes — **both normally exist**.

Because:

| Location                               | Purpose               |
| -------------------------------------- | --------------------- |
| `packages/design-system/styled-system` | used by DS components |
| `apps/client/styled-system`            | used by the app       |

------

# 4️⃣ But They Are NOT Independent

The **client should use the design system preset**.

Meaning:

```ts
// apps/client/panda.config.ts
import { designSystemPreset } from '@workspace/design-system/panda.preset'
```

Then Panda merges:

```text
design system tokens
+
app tokens
```

to generate:

```text
apps/client/styled-system
```

------

# 5️⃣ Which One Would You Remove?

If you had to remove one:

```text
❌ apps/client/styled-system
```

would be regenerated automatically.

You **never remove the DS one**, because the DS **build depends on it**.

# Why this breaks everything

Your design system exports:

```
panda.preset
```

which **is used by Panda during build time**.

But your DS bundle is built for **browser**.

Panda expects **Node-compatible code**.

So Rollup/Vite tries to polyfill Node modules and fails.

------

# 3️⃣ The Fix (critical)

Change this in `tsdown.config.ts`:

```ts
platform: 'browser'
```

to:

```ts
platform: 'neutral'
```

or remove it entirely.

Correct config:

```ts
export default defineConfig({
  entry: { ... },
  format: ['esm'],
  platform: 'neutral',
  dts: true,
  sourcemap: true,
  logLevel: 'silent',
  unbundle: true,
  deps: {
    neverBundle: ['react', 'react-dom', '@ark-ui/react', '@workspace/icons'],
  },
})
```

This prevents Node APIs from being stripped incorrectly.
