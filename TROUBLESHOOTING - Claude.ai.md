**On the two `styled-system/` folders:**

**`packages/design-system/styled-system/`** is generated by `panda codegen` running inside the DS package. It contains the full Panda type infrastructure — `css()`, `cva()`, `recipes`, token types — that the DS source files (`src/`) import from. It's the DS's *own* codegen output, used at DS build time.

**`apps/client/styled-system/`** is generated by `panda codegen` running inside the client app. It consumes the `designSystemPreset` from the DS and generates the *same* infrastructure for the client's own source files to import from.

They look identical but serve different compilation contexts. The DS needs its own to build itself. The client needs its own to build itself.

**Are both necessary?** Yes — but for a specific reason worth understanding. The client can't just re-use the DS's `styled-system/` because Panda codegen scans *source files* for class usage and only generates what it finds. The DS scans DS source files; the client scans client source files. If they shared one output, either the DS would have to scan client files (wrong direction) or the client would be missing classes it uses.

**Could you remove one?** The only one you could theoretically remove is the DS's `styled-system/` — if you moved all DS source files to use raw CSS custom properties instead of Panda's `css()` utility. That's a big refactor and not worth it. Both stay.

Found the issues. There are three distinct problems here.

------

**Problem 1 — `platform: 'browser'` on `panda.preset`**

`panda.preset.ts` runs in Node (consumed by `panda.config.ts` at build time, never in the browser). With `platform: 'browser'`, tsdown externalises Node built-ins like `createRequire` as `__vite-browser-external` — which is what you're seeing in screenshots 5, 6, 7. The preset entry needs `platform: 'node'` while everything else stays `'browser'`.

**Problem 2 — dist file extensions**

Your `package.json` exports reference `.js` / `.d.ts` but the previous working config (from earlier in this thread) was building `.mjs` / `.d.mts`. tsdown's default output extension with `format: ['esm']` depends on the version — with `tsdown: "*"` you're getting whatever the latest resolves to. The extensions need to be explicit and match what's declared in `exports`.

**Problem 3 — `forms/primitives` export is gone**

The old working config had `'forms/primitives': 'src/forms/primitives.ts'` as an entry. It's commented out in the new config but the client may still be importing it.

------

Here's the fixed `tsdown.config.ts`:

```ts
import { defineConfig } from 'tsdown';

const browserEntries = {
  'index':           'src/index.ts',
  'tokens/index':    'src/tokens/index.ts',
  'recipes/index':   'src/recipes/index.ts',
  'components/index':'src/components/index.ts',
  'grid/index':      'src/grid/index.ts',
  'forms/index':     'src/forms/index.ts',
  'viewport/index':  'src/viewport/index.ts',
  'palette/colors':  'src/palette/colors.palette.ts',
};

// panda.preset runs in Node at build time — must be built separately
const nodeEntries = {
  'panda.preset': 'src/panda.preset.ts',
};

export default defineConfig([
  {
    entry:    browserEntries,
    format:   ['esm'],
    platform: 'browser',
    dts:      true,
    sourcemap: true,
    unbundle: true,
    deps: {
      neverBundle: ['react', 'react-dom', '@ark-ui/react', '@workspace/icons'],
    },
  },
  {
    entry:    nodeEntries,
    format:   ['esm'],
    platform: 'node',
    dts:      true,
    sourcemap: true,
  },
]);
```

And the `package.json` exports — match the actual extensions tsdown produces. With `format: ['esm']` and no explicit `outExtensions`, tsdown currently outputs `.js` / `.d.ts` (not `.mjs`). Your current exports already use `.js` so that should be fine — but pin `tsdown` to a specific version so it doesn't shift under you:

```json
"tsdown": "^0.20.3"
```

Replace `"tsdown": "*"` with that.
