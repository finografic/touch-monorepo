# HMR (Hot Module Replacement) Setup for i18n Messages

📅 Oct 19, 2025

## 🎯 TL;DR - Which Files to Use?

### ✅ **USE: Source TypeScript Files**

```
/packages/i18n/src/messages/app/messages.{locale}.ts
```

**Why?**
- ✅ HMR works perfectly
- ✅ Edit and see changes instantly
- ✅ Full TypeScript type safety
- ✅ No build step needed during development

### ❌ **DON'T USE: Generated/Compiled Files**

```
/config/generated/i18n/app/messages/*.json     ❌ ParaglideJS generated
/packages/i18n/dist/messages/app/*.js          ❌ tsup compiled (production only)
```

**Why NOT?**
- ❌ No HMR - requires rebuild
- ❌ Can't edit directly - source changes overwrite them
- ❌ Extra build step slows development

## 📁 Three Message Locations Explained

### 1. **Source Files** (Development) ✅

```
/packages/i18n/src/messages/app/
├── messages.en-GB.ts    # Edit these during development!
├── messages.es-ES.ts    # HMR works perfectly
└── index.ts             # Export logic
```

**Purpose:** Development source files with HMR
**Usage:** Import directly via `@workspace/i18n`

### 2. **Compiled Dist** (Production)

```
/packages/i18n/dist/messages/app/
├── messages.en-GB.js    # Built by tsup
├── messages.es-ES.js    # For production use
└── index.js             # Compiled exports
```

**Purpose:** Production build artifacts
**Usage:** Consumed by apps in production

### 3. **ParaglideJS Generated** (Optional)

```
/config/generated/i18n/app/messages/
├── en-GB.json          # Generated by ParaglideJS
└── es-ES.json          # From JSON source files
```

**Purpose:** Optional ParaglideJS function generation
**Usage:** Not currently used (commented out in vite.config)

## ⚙️ Vite Configuration

### Current Setup (Optimal for HMR)

```typescript
// vite.config.ts
resolve: {
  alias: {
    // Points to SOURCE files for HMR during development
    '@workspace/i18n': resolve(workspaceRoot, 'packages/i18n/src/index.ts'),
    '@workspace/i18n/messages': resolve(workspaceRoot, 'packages/i18n/src/messages'),
  },
},
plugins: [
  // ParaglideJS plugin DISABLED for custom TS messages with HMR
  // paraglidePlugin({ project: '../../packages/i18n' }),
]
```

### Why This Works

1. **Development:** Vite resolves to source `.ts` files
2. **HMR:** Vite watches source files and hot-reloads changes
3. **TypeScript:** Vite transforms TS → JS on the fly
4. **Production:** Your build process uses compiled `dist/` folder

## 🚀 Development Workflow

### Step 1: Edit Source Files

```typescript
// packages/i18n/src/messages/app/messages.en-GB.ts
export const messages = {
  admin: {
    pages: {
      dashboard: {
        title: 'Dashboard',  // Edit this
        description: 'System overview'  // HMR updates immediately!
      }
    }
  }
};
```

### Step 2: Use in Components

```typescript
// apps/client/src/admin/AdminDashboardPage.tsx
import { getMessages } from '@workspace/i18n';

const { currentLanguage } = useAppConfig();
const messages = getMessages(currentLanguage);

// Auto-updates when you edit the source file!
const title = messages.admin.pages.dashboard.title;
```

### Step 3: See Changes Instantly

- Save the TS file
- Vite HMR kicks in
- Component re-renders with new text
- **No rebuild needed!** ⚡

## 🏗️ Production Build

### Build Process

```bash
# In packages/i18n
pnpm build  # Compiles TS → JS in dist/

# In apps/client
pnpm build  # Uses compiled dist/ folder
```

### What Happens

1. tsup compiles `src/messages/` → `dist/messages/`
2. Production build uses `dist/` folder
3. Source files stay clean for development
