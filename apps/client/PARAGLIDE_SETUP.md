# ParaglideJS Setup - Touch Monorepo

## Overview

Successfully integrated `@inlang/paraglide-js` for type-safe, compile-time i18n alongside existing `i18next-react` setup. This allows gradual migration from i18next to ParaglideJS.

## Project Structure

```
apps/client/
├── messages/
│   ├── en-GB.json          # English (GB) translations (flat, snake_case keys)
│   └── es-ES.json          # Spanish (Spain) translations (flat, snake_case keys)
├── project.inlang/
│   └── settings.json       # Inlang project configuration
├── src/
│   └── paraglide/          # Generated by ParaglideJS (DO NOT EDIT)
│       ├── messages.js     # Main export (m namespace)
│       ├── messages/       # Individual message functions
│       ├── runtime.js      # Locale management
│       └── ...
└── vite.config.ts          # Vite + ParaglideJS plugin config
```

## Key Design Decisions

### 1. **Flat Snake_Case Keys** (Following Inlang Best Practices)

```json
{
  "admin_dashboard_title": "Dashboard",
  "admin_dashboard_title_role": "Dashboard - {role}",
  "admin_dashboard_description": "System overview"
}
```

**Benefits:**
- ✅ Direct function calls with tree-shaking
- ✅ Better IDE autocomplete
- ✅ Cleaner imports
- ✅ No runtime overhead

**vs. Nested Keys** (old approach):

```json
{
  "admin": {
    "dashboard": {
      "title": "Dashboard"
    }
  }
}
```

### 2. **Locale Format: `en-GB`, `es-ES`**

- Maintains consistency with existing app configuration
- Works seamlessly with `useAppConfig().currentLanguage`
- ParaglideJS fully supports this format

### 3. **Location: `apps/client/messages/`**

- Messages live directly in the client app (not in `packages/i18n`)
- Aligns with monorepo best practices (see example projects)
- Simplifies build pipeline
- Better HMR during development

### 4. **Generated Code: `apps/client/src/paraglide/`**

- Type-safe generated functions
- No runtime dependencies
- Extremely fast (compile-time)
- Tree-shakeable (unused messages eliminated)

## Configuration Files

### `project.inlang/settings.json`

```json
{
  "$schema": "https://inlang.com/schema/project-settings",
  "baseLocale": "en-GB",
  "locales": ["en-GB", "es-ES"],
  "modules": [
    "https://cdn.jsdelivr.net/npm/@inlang/plugin-message-format@4/dist/index.js",
    "https://cdn.jsdelivr.net/npm/@inlang/plugin-m-function-matcher@2/dist/index.js"
  ],
  "plugin.inlang.messageFormat": {
    "pathPattern": "./messages/{locale}.json"
  }
}
```

**Plugins:**
- `@inlang/plugin-message-format` - Handles message format parsing
- `@inlang/plugin-m-function-matcher` - Enables the `m` function pattern

### `vite.config.ts`

```typescript
import { paraglideVitePlugin } from '@inlang/paraglide-js';

export default defineConfig({
  plugins: [
    paraglideVitePlugin({
      project: './project.inlang',
      outdir: './src/paraglide',
    }),
    // ... other plugins
  ],
});
```

## Usage Examples

### Basic Message (No Parameters)

```typescript
import { m } from 'src/paraglide/messages.js';

const title = m.admin_dashboard_title(); // "Dashboard"
```

### Message with Dynamic Parameters

```typescript
import { m } from 'src/paraglide/messages.js';

const role = 'admin';
const title = m.admin_dashboard_title_role({ role });
// English: "Dashboard - admin"
// Spanish: "Panel de Control - admin"
```

### Setting Locale (Sync with App Config)

```typescript
import { setLocale } from 'src/paraglide/runtime.js';
import { useAppConfig } from 'providers/AppConfigProvider';

const { currentLanguage } = useAppConfig();

// Sync ParaglideJS locale with app language
React.useEffect(() => {
  setLocale(currentLanguage as 'en-GB' | 'es-ES');
}, [currentLanguage]);
```

### Full Component Example

```typescript
import React from 'react';
import { m } from 'src/paraglide/messages.js';
import { setLocale } from 'src/paraglide/runtime.js';
import { useAppConfig } from 'providers/AppConfigProvider';
import { useAuth } from 'providers/AuthProvider';

export const AdminDashboardPage: React.FC = () => {
  const { currentLanguage } = useAppConfig();
  const { user } = useAuth();

  // Sync locale
  React.useEffect(() => {
    setLocale(currentLanguage as 'en-GB' | 'es-ES');
  }, [currentLanguage]);

  const role = user?.role || 'admin';

  return (
    <AdminPageLayout
      title={m.admin_dashboard_title_role({ role })}
      subtitle={m.admin_dashboard_description()}
    >
      {/* content */}
    </AdminPageLayout>
  );
};
```

## Workflow

### Adding New Translations

1. **Edit JSON files**:

```json
// messages/en-GB.json
{
  "new_feature_title": "New Feature",
  "new_feature_description": "Description with {param}"
}
```

2. **Regenerate** (automatic with Vite HMR, or manual):

```bash
npx @inlang/paraglide-js compile --project ./project.inlang --outdir ./src/paraglide
```

3. **Use in code**:

```typescript
import { m } from 'src/paraglide/messages.js';

m.new_feature_title(); // "New Feature"
m.new_feature_description({ param: 'value' }); // "Description with value"
```

### Checking Translation Completeness

Use Inlang CLI (already installed in `packages/i18n`):

```bash
cd packages/i18n
npx @inlang/cli lint
```

Or create a similar script in `apps/client/` for local messages.

## Migration Strategy

### Phase 1: Co-existence ✅ (Current)

- ParaglideJS and i18next run side-by-side
- Start with simple, static translations (admin page titles)
- Test HMR, type-safety, and locale syncing

### Phase 2: Gradual Migration

1. Migrate admin pages (low user traffic)
2. Migrate components one by one
3. Keep i18next for complex pluralization until ParaglideJS patterns established

### Phase 3: Full Migration (Future)

- Remove i18next dependencies
- Update all translations to ParaglideJS
- Delete `packages/i18n/src/translations/` (old nested JSON)

## Comparison: ParaglideJS vs. i18next

| Feature | ParaglideJS | i18next |
|---------|-------------|---------|
| **Type Safety** | ✅ Full (compile-time) | ❌ Runtime only |
| **Bundle Size** | ✅ Tiny (tree-shaken) | ❌ Larger runtime |
| **Performance** | ✅ Instant (no parsing) | ⚠️ Runtime parsing |
| **IDE Support** | ✅ Excellent autocomplete | ⚠️ String-based |
| **Pluralization** | ✅ Built-in | ✅ Built-in |
| **Interpolation** | ✅ Type-checked params | ⚠️ String-based |
| **Nesting** | ❌ Use flat keys instead | ✅ Supports nesting |
| **HMR** | ✅ Fast | ✅ Good |
| **Learning Curve** | ⚠️ New patterns | ✅ Well-known |

## Benefits of This Setup

1. **Type Safety**: Compile-time errors for missing translations or wrong parameters
2. **Performance**: No runtime overhead, smallest possible bundle
3. **DX**: Amazing autocomplete, instant feedback
4. **Co-existence**: Can migrate gradually without breaking existing code
5. **Maintainability**: Flat structure is easier to understand and search
6. **Tooling**: Inlang ecosystem (VS Code extension, Fink editor, CLI)

## Potential Issues & Solutions

### Issue: Locale Not Syncing

**Solution**: Make sure `setLocale()` is called when `currentLanguage` changes:

```typescript
React.useEffect(() => {
  setLocale(currentLanguage as 'en-GB' | 'es-ES');
}, [currentLanguage]);
```

### Issue: Messages Not Updating

**Solution**: Regenerate paraglide output:

```bash
npx @inlang/paraglide-js compile --project ./project.inlang --outdir ./src/paraglide
```

### Issue: Type Errors After Adding Messages

**Solution**: Restart TypeScript server in VSCode (`Cmd+Shift+P` → "Restart TS Server")
